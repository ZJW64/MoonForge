# 一页项目说明 · MoonForge

**项目名**　MoonForge（月铸）
**一句话**　MoonBit 的源码到源码派生代码生成器：读取 `.mbt` 中的类型定义与 `impl @derive.DeriveXxx for T` 标记，按可插拔规则生成 MoonBit 源码，并在构建前自动生成 / 校验。
**选题方向**　语言与开发工具
**仓库**　<https://github.com/ZJW64/MoonForge>（公开）
**许可证**　Apache-2.0（非移植项目，未复制任何第三方代码）

---

## 问题：MoonBit 的 `derive` 无法扩展，且编译器短期内不会开放注册点

官方文档 [E4077](https://docs.moonbitlang.com/zh-cn/latest/language/error_codes/E4077.html) 明确写着："**你无法让 MoonBit 自动派生你自定义的特征**"。派生注册表在编译器内部（`src/ast_derive.ml` 里是一张硬编码的 `Trait → Deriver` 哈希表），编译器也没有暴露 AST、没有 proc-macro、没有 comptime。

于是"为自定义类型批量生成语义化代码"（数据校验、字段名枚举、结构化 diff、Builder、访问者）只能逐类型手写——**重复、易漏、随字段变更而漂移**。

## 方案：不要求编译器开口子，而是把能力做在用户态

用 **100% MoonBit** 实现一条源码到源码的生成流水线：

```
.mbt 源码 → 词法 → 子集语法分析 → 类型模型 IR → 规则分派 → 代码生成 → 同目录 *_derive_gen.mbt → 与手写代码一起编译
```

它不是"四条规则加一个脚本"，而是一套**通用 trait 派生基础设施**。派生这件事由三段构成，
每一段都是语言里真实存在的东西：

| 段 | 是什么 | 举例 |
|---|---|---|
| **目标 trait** | "能做什么"，普通 MoonBit trait | `trait Validate { fn validate(Self) -> Result[Unit, String] }` |
| **标记 trait** | "这个类型请求了这次派生" | `trait DeriveValidate { fn requested(Self) -> Unit }` |
| **规则** | "怎么从类型定义生成实现"，实现 SPI trait `DeriveRule` | `ValidateRule` |

三处关键设计：

1. **派生入口是真实的 trait impl，不是 doc comment。**
   用户在类型所在文件写一行 `pub impl @derive.DeriveValidate for User with fn requested(_self) {}`。
   它是**语言级**的"该类型请求了某次派生"，因此 **`moon check` 会真实编译它** ——
   标记名拼错在编译期就暴露，任何工具也能读懂这条请求。
   （入口刻意**不用** `derive(...)`：它只认编译器内置 trait 白名单，对自定义 trait 直接
   报 `Don't know how to derive trait X`，所以它当不了扩展入口。）
2. **规则是一等公民。** 规则本身是一个 `pub(open) trait DeriveRule`，规则集合是
   `Array[&DeriveRule]` 的**异构 trait 对象数组**，显式传给 `generate(...)`。
   第三方可以只依赖本包、把自己的规则并进集合，**不改 MoonForge 任何一行代码**。
3. **生成到源文件同目录 + 生成物提交进仓库 + CI 漂移检查。**
   MoonBit 的包边界是目录，私有字段只有同包可见；生成到同目录才能**直接访问字段，
   不必强迫用户把字段改成 `pub`**。输出字节稳定，`moonforge check` 在源文件改动而
   生成物未更新时返回非零。这让"生成代码"从一次性脚本变成可持续维护的工程资产。

## 本期交付范围

| 内容 | 说明 |
|---|---|
| 词法 + 子集语法分析 + 类型模型 IR | 只在花括号深度 0 认 `struct` / `enum`，函数体整体跳过；并识别 `impl <前缀>.<标记> for <类型>`（含泛型目标、排除固有 impl）；IR 用 `BodyKind` 区分"有具名字段 / 位置参数 / 无字段体" |
| **派生基础设施** | `moonforge/derive`：4 个目标 trait + 4 个标记 trait；`DeriveRule` SPI + 异构规则对象数组 + 三类可操作诊断 |
| **4 条内置规则** | `field_names`、`validate`（注解驱动）、`diff`、`to_pairs` |
| **第三方扩展样例** | `examples/extension/`：自带目标 trait / 标记 trait / 规则的完整可运行扩展，全程未改内核源码 |
| CLI | `list-rules` / `explain` / `gen` / `check`，退出码契约 `0` / `1` / `2` |
| 测试 | **11 层、119 个用例，`js` 与 `wasm-gc` 两个后端全部通过** |
| 一键验收 | `bash scripts/e2e.sh` 复现 CI 全部 6 个阶段（漂移 / 测试 / 真编译 / 格式化与列宽预算 / CRLF 容忍 / 退出码契约） |
| 示例 | `examples/` 含输入、已提交的生成物、以及直接调用生成代码的端到端测试 |

**明确不做**：不是编译器插件，不依赖编译器内部 API，不做运行时反射，不声称扩展了 `derive()`，不是 comptime（生成发生在构建之前的独立阶段）。

## 创新点（可验证表述）

1. **在用户态补上了 MoonBit 缺失的派生注册点**：依据 E4077，`derive()` 无法扩展；MoonForge 用**合法语法**（真实 trait impl）而非修改编译器，实现了"为自定义类型注册派生规则"的等价体验。
2. **入口是语言级事实，而不是工具私有约定**：标记 impl 能被 `moon check` 编译、能被任何工具读懂；拼错标记名在编译期就暴露。
3. **规则集是可替换的 trait 对象数组**：新增规则不需要触碰核心代码，第三方也不必成为工具的一部分（`examples/extension/` 是证据）。
4. **生成物可进版本库、可被 CI 校验漂移**：字节稳定 + `check` 子命令，使生成代码成为可持续维护的资产；生成代码由编译器裁决正确性。
