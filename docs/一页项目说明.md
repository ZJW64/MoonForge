# 一页项目说明 · MoonForge

**项目名**　MoonForge（月铸）
**一句话**　MoonBit 的源码到源码派生代码生成器：读取 `.mbt` 中的类型定义与 `/// @derive(...)` 标记，按可插拔规则生成 MoonBit 源码，并在构建前自动生成 / 校验。
**选题方向**　语言与开发工具
**仓库**　<https://github.com/ZJW64/MoonForge>（公开）
**许可证**　Apache-2.0（非移植项目，未复制任何第三方代码）

---

## 问题：MoonBit 的 `derive` 无法扩展，且编译器短期内不会开放注册点

官方文档 [E4077](https://docs.moonbitlang.com/zh-cn/latest/language/error_codes/E4077.html) 明确写着："**你无法让 MoonBit 自动派生你自定义的特征**"。派生注册表在编译器内部（`src/ast_derive.ml` 里是一张硬编码的 `Trait → Deriver` 哈希表），编译器也没有暴露 AST、没有 proc-macro、没有 comptime。

于是"为自定义类型批量生成语义化代码"（数据校验、字段名枚举、结构化 diff、Builder、访问者）只能逐类型手写——**重复、易漏、随字段变更而漂移**。

## 方案：不要求编译器开口子，而是把能力做在用户态

用 **100% MoonBit** 实现一条源码到源码的生成流水线：

```
.mbt 源码 → 词法 → 子集语法分析 → 类型模型 IR → 规则分派 → 代码生成 → 同目录 *_derive_gen.mbt → 与手写代码一起编译
```

三处关键设计：

1. **请求语法零侵入**：派生需求写在 **doc comment** 里（`/// @derive(validate, diff)`），不新增 attribute、不修改语法，IDE 与 `moon fmt` 都不会报错。
2. **生成到源文件同目录**：MoonBit 的包边界是目录，私有字段只有同包可见；生成到同目录才能**直接访问字段，不必强迫用户把字段改成 `pub`**。
3. **生成物提交进仓库 + CI 漂移检查**：输出字节稳定，`moonforge check` 在源文件改动而生成物未更新时返回非零。这让"生成代码"从一次性脚本变成可持续维护的工程资产。

## 本期交付范围

| 内容 | 说明 |
|---|---|
| 词法 + 子集语法分析 + 类型模型 IR | 只在花括号深度 0 认 `struct` / `enum`，函数体整体跳过；IR 用 `BodyKind` 区分"有具名字段 / 位置参数 / 无字段体" |
| 规则接口与注册表 | `Rule` 是公开的普通值，扩展一条规则 = 加一个文件 + 注册表加一项 |
| **4 条内置规则** | `field_names`、`validate`（注解驱动）、`diff`、`to_pairs` |
| CLI | `list-rules` / `explain` / `gen` / `check`，退出码契约 `0` / `1` / `2` |
| 测试 | **10 层、96 个用例，`js` 与 `wasm-gc` 两个后端全部通过** |
| 一键验收 | `bash scripts/e2e.sh` 复现 CI 全部 6 个阶段（漂移 / 测试 / 真编译 / 格式化稳定性 / CRLF 容忍 / 退出码契约） |
| 示例 | `examples/` 含输入、已提交的生成物、以及直接调用生成代码的端到端测试 |

**明确不做**：不是编译器插件，不依赖编译器内部 API，不做运行时反射，不声称扩展了 `derive()`，不是 comptime（生成发生在构建之前的独立阶段）。

## 创新点（可验证表述）

1. **在用户态补上了 MoonBit 缺失的派生注册点**：依据 E4077，`derive()` 无法扩展；MoonForge 用合法语法（doc comment）而非修改编译器，实现了"为自定义类型注册派生规则"的等价体验。
2. **生成物可进版本库、可被 CI 校验漂移**：字节稳定 + `check` 子命令，使生成代码成为可持续维护的资产。
3. **生成的代码由编译器裁决正确性**：生成物随仓库提交并被 `moon check` 覆盖。
4. **规则是一等公民而非插件配置**：新增规则不需要触碰核心代码。
