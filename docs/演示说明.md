# 可复现演示说明 · MoonForge

> 目标：让评委在一台装有 MoonBit 工具链的机器上，**5 分钟内**完整复现从"写类型定义"到"生成代码被编译器验证"的全过程，并亲手看到漂移检查拦住一次错误提交。

## 0. 环境准备

| 依赖 | 版本 | 说明 |
|---|---|---|
| MoonBit CLI | `moon 0.1.20260915` 或更新 | 本仓库的格式化基线就是这条版本（见 `.github/workflows/ci.yml` 注释）。安装：`curl -fsSL https://cli.moonbitlang.com/install/unix.sh \| bash`；Windows 用官方 PowerShell 安装脚本，或见 [moonbitlang.com/download](https://www.moonbitlang.com/download/) |

## 2. 分步演示（讲清楚每一环在做什么）

### 2.1 看工具认识哪些规则

```bash
$ moon run cmd/main -- list-rules
已注册的派生规则（用法：在类型的 doc comment 里写 `@derive(<规则名>)`）：

  field_names
      为 struct 生成 T::field_names() -> Array[String]，顺序与字段声明一致
  validate
      为 struct 生成 T::validate(self) -> Result[Unit, String]，由字段注解 @nonempty/@min/@max/@positive 驱动
  diff
      为 struct 生成 T::diff(self, other) -> Array[String]，返回发生变化的字段名（字段类型需实现 Eq）
  to_pairs
      为 struct 生成 T::to_pairs(self) -> Array[(String, String)]，只包含 String 字段（其余字段跳过并留说明行）
```

### 2.2 看一份真实的输入

打开 `examples/models.mbt`。它就是**普通 MoonBit 代码**，没有任何新语法：

```moonbit
///|
/// 用户信息。
///
/// `to_pairs` 只收 `String` 字段：`age` 是 Int，工具不会替用户决定
/// "Int 该怎么变成字符串"，因此跳过并在生成文件里留下说明行。
///
/// @derive(validate, diff, field_names, to_pairs)
pub(all) struct User {
  /// 姓名
  /// @nonempty
  name : String
  /// 年龄
  /// @min(0) @max(150)
  age : Int
  /// 电子邮箱 —— 没有校验注解，因此不会产生任何检查代码
  email : String
} derive(Eq, Debug)
```

同一个文件里还有另外三个"反面样本"，它们是演示的重点：

| 声明 | 演示什么 |
|---|---|
| `Order` | `quantity` 是 `Int` 却写了 `@nonempty` → **跳过并留说明行**，不生成语义可疑的代码 |
| `enum Status` | 没有 `@derive` → 工具**完全不碰**（零侵入） |
| `struct Point(Int, Int)` | 有 `@derive` 但**没有具名字段** → **拒绝生成并说清原因**，而不是生成 `field_names() { [] }` |

重点看两处：

- `Order.quantity`：写了 `@nonempty` 但类型是 `Int`，工具**跳过而不是硬塞检查**，并在生成文件里留下说明行；
- `Point`：`body_label` 明确标出 `struct(位置参数)`，三条规则各自给出"为什么不适用"——**"不生成"和"生成"一样要被解释**。

### 2.4 生成

```bash
$ moon run cmd/main -- gen examples
  [warn] models.mbt: 规则 `field_names` 不适用于 Point（第 72 行）：Point 是位置参数（元组）结构体，没有具名字段
  [warn] models.mbt: 规则 `validate` 不适用于 Point（第 72 行）：Point 是位置参数（元组）结构体，没有具名字段
  [warn] models.mbt: 规则 `diff` 不适用于 Point（第 72 行）：Point 是位置参数（元组）结构体，没有具名字段
  generated examples/models_derive_gen.mbt  [User.validate, User.diff, User.field_names, User.to_pairs, Order.field_names, Order.validate, Order.diff]

moonforge: 扫描 2 个源文件，生成 1 个，清理 0 个，警告 3 条
```

打开 `examples/models_derive_gen.mbt` 查看生成结果，注意：

- 文件头写明版本、来源与重现命令：
  `// Generated by MoonForge 0.2.0 -- DO NOT EDIT.`；
- 说明行 `// moonforge: 跳过 Order.quantity 的校验注解（类型 Int 不在 ... 白名单内）` 解释了"为什么不生成"；
- **生成方法在仓库里没有任何手写实现**。

> `gen` 是**幂等**的：连跑两次，输出**逐字节相同**（`codegen_wbtest.mbt` 里有断言）。
> 它还会**清理残留生成物**：源文件里已经没有 `@derive` 时，同名的 `*_derive_gen.mbt` 会被删除，
> 避免 `check` 一直报"多余的生成文件"而 `gen` 又修不好的死循环。

### 2.5 关键一步：让编译器来裁决

生成物是**提交进仓库**的，所以它一直在参与编译：

```bash
$ moon check
Finished. moon: no work to do   # 关键是没有错
```

**反证**：把生成文件删掉，`moon check` 会立刻失败——说明编译检查确实覆盖了生成代码。

```bash
$ rm examples/models_derive_gen.mbt && moon check   # 失败：找不到 User::validate
$ moon run cmd/main -- gen examples && moon check   # 恢复
```

### 2.6 让生成代码真跑起来

`examples/models_wbtest.mbt` 里的测试**直接调用自动生成的方法**：

```moonbit
@debug.debug_inspect(u.validate(), content="Err(\"User.name must not be empty\")")
@debug.debug_inspect(a.diff(b), content="[\"age\"]")
@debug.debug_inspect(u.to_pairs(), content="[(\"name\", \"Ada\"), (\"email\", \"ada@example.com\")]")
```

```bash
$ moon test --target js
Total tests: 96, passed: 96, failed: 0.

$ moon test --target wasm-gc
Total tests: 96, passed: 96, failed: 0.
```

换后端再跑一遍是有意义的：两个后端的整数语义与字符串表示不同，生成代码不能只在其中一个后端成立。

### 2.7 演示漂移检查（CI 的核心价值）

> 下面在 `_build/` 的副本里做，**不动仓库**；`scripts/e2e.sh` 第 6 阶段就是同一套动作。

```bash
$ mkdir -p _build/demo && cp examples/models.mbt _build/demo/

# 改动源文件但故意不重新生成
$ printf '\n///\n/// @derive(field_names)\nstruct DriftProbe {\n  k : String\n}\n' >> _build/demo/models.mbt

$ moon run cmd/main -- check _build/demo
  [drift] 内容过期：_build/demo/models_derive_gen.mbt
moonforge: 检测到 1 处生成物漂移（已扫描 1 个文件）。
请运行 `moon run cmd/main -- gen <dir>` 重新生成并提交。
$ echo $?
1

# 重新生成后恢复
$ moon run cmd/main -- gen _build/demo
$ moon run cmd/main -- check _build/demo
moonforge: 已扫描 1 个源文件，生成物与源文件一致，无漂移
```

**这里有一个值得讲的细节**：`check` 的"未过期"判定是基于**源文件重新生成一遍、再和磁盘上的字节对比**，而不是比对时间戳。所以它不依赖文件系统时间精度，跨机器、跨时区、`git clone` 之后（源码与生成物的 mtime 顺序不可控）结果都一样。

退出码约定：`0` 成功；`1` 检出漂移；`2` 参数或路径有误。任何错误都会落成**一行** `moonforge: ...` 提示，不会把运行期堆栈喷进 CI 日志。

| 命令 | 触发场景 | 退出码 |
|---|---|---|
| `moonforge check <dir>` | 源文件与生成物一致 | `0` |
| `moonforge check <dir>` | 源文件改过、生成物未更新 | `1` |
| `moonforge check <path>` | `path` 不存在 / 不是 `.mbt` / 目录里没有 `.mbt` | `2` |

最后一行是刻意加的防"假绿"：以前路径写错会静默返回 0，CI 显示绿色但一个文件都没检查。

把 `check` 接进 CI（见 `.github/workflows/ci.yml`），"改了源码却忘记重新生成"就再也不会被合并进去。

### 2.8 跨后端验证

CLI 的 `@derive` 解析、文件读写与 `check` 在 `js` 与 `wasm-gc` 两个后端行为一致：

```bash
$ moon run cmd/main --target wasm-gc -- check examples
moonforge: 已扫描 2 个源文件，生成物与源文件一致，无漂移
```

唯一的跨后端差异在**出错路径**：`js` 后端能干净地返回非零退出码；`wasm-gc` 没有标准的退出原语，友好提示行会先打印，随后附带一段 `RuntimeError: unreachable` 回溯。因此 CI 中的漂移检查固定使用默认的 `js` 后端（见 `.github/workflows/ci.yml`）。

## 3. 扩展一条新规则

演示"可扩展"不是口号。完整步骤见 [`扩展规则指南.md`](扩展规则指南.md)，浓缩版：

1. 新建 `rules/<规则名>.mbt`，写一个返回 `@forge.Rule` 的公开函数（参考 `rules/to_pairs.mbt`，约 30 行）；
2. 在 `rules/registry.mbt` 的 `all()` 数组里加一项；
3. 在 `rules/rules_wbtest.mbt` 补一组用例（正例 + 不适用 + 白名单外跳过）；
4. `moon test --target js` 通过即完成。

**不需要修改词法、语法、代码生成等任何核心代码。**

想动手试试的话，有一个天然的练习题：把 `to_pairs` 改造成 `to_json`——它不是简单换个名字，因为
"如何把 `Int` / `Bool` / 嵌套类型转成 JSON 字面量"必须由规则自己决定；这正是本项目
"规则是一等公民"设计的价值所在。`to_pairs` 本身就是按这套流程加进来的第 4 条规则。

## 4. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `moon check` 报 `Cannot load the core file` | 工具链安装不完整，重新执行官方安装脚本 |
| `moon run` 报找不到命令 | 未把 `$HOME/.moon/bin`（Windows 为 `%USERPROFILE%\.moon\bin`）加入 `PATH` |
| `moon fmt --check` 失败 | 仓库里有未格式化的文件，跑一次 `moon fmt` 并提交。注意它有差异时给的是**非零**退出码（本机实测为 `127`），不是 `1` |
| `check` 报漂移但我没改源码 | 先确认生成物**已提交**（不要写进 `.gitignore`）。CRLF/LF 差异**不会**造成误报——读取时会先归一化换行符；`scripts/e2e.sh` 第 5 阶段固化了这条 |
| `explain` 里看不到我的 `@derive` | doc comment 与声明之间有空行；注释必须**紧邻**声明 |
| 规则报"未注册" | 规则名拼写正确但没注册；用 `list-rules` 核对 |
| 规则报"名字不合法" | 规则名含大写字母或非法字符。合法名只允许小写字母 / 数字 / 下划线——这两种情况工具给的是**不同的诊断**，不会混在一起 |
| 规则报"不适用" | 该类型没有具名字段（enum / 位置参数结构体 / 没写字段体）。加标记是安全的，不会报错也不会产出错误代码 |
| `explain` 报"找不到路径"/"是目录" | `explain` 只接受**单个 `.mbt` 文件**，不能传目录或规则名；正确用法 `moon run cmd/main -- explain examples/models.mbt` |
| 想在脚本里判断结果 | 看退出码：`0` 成功 / `1` 检出漂移 / `2` 参数或路径有误 |
