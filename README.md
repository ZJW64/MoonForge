# MoonForge

> **MoonBit 的源码到源码派生代码生成器。**
> 读取 `.mbt` 里的类型定义与 `/// @derive(...)` 标记，按可插拔规则生成 MoonBit 源码，
> 并在构建前自动生成 / 校验——让"为自定义类型批量生成样板代码"变成一条命令。

```
$ moon run cmd/main -- list-rules

已注册的派生规则（用法：在类型的 doc comment 里写 `@derive(<规则名>)`）：

  field_names
      为 struct 生成 T::field_names() -> Array[String]，顺序与字段声明一致
  validate
      为 struct 生成 T::validate(self) -> Result[Unit, String]，由字段注解 @nonempty/@min/@max/@positive 驱动
  diff
      为 struct 生成 T::diff(self, other) -> Array[String]，返回发生变化的字段名（字段类型需实现 Eq）
```    

## 1. 它帮我们解决什么问题

MoonBit 的 `derive(...)` **只覆盖编译器内置的 trait 白名单**。官方文档 [E4077](https://docs.moonbitlang.com/zh-cn/latest/language/error_codes/E4077.html) 明写：

> "MoonBit 允许你为你的类型派生一些预定义特征的实现。这意味着**你无法让 MoonBit 自动派生你自定义的特征**。"
>
> 示例 `struct A(Int) derive(T)`（`T` 为用户自定义 trait）直接编译失败。

派生注册表位于编译器内部（`moonbitlang/moonbit-compiler` 的 `src/ast_derive.ml` 里是一张硬编码的 `Trait → Deriver` 哈希表），**没有对外的注册入口**；编译器也没有暴露 AST、没有 proc-macro、没有 comptime。

结果就是：一旦需要"为自定义类型批量生成**语义化**代码"——数据校验、字段名枚举、结构化 diff、Builder、访问者——开发者只有两条路：

- 逐类型手写样板代码 → **重复、易漏、随字段变更而漂移**；
- 用外部通用代码生成器 → **脱离包边界、拿不到私有字段、和 `moon build` 割裂**。

**MoonForge 在用户态补上了这个派生注册点**：不修改编译器、不依赖编译器内部 API，用"源码到源码"的方式把这类代码生成变成可测试、可持续维护的工程资产。

## 2. 它明确不是什么

主动划清边界，避免夸大：

- ❌ **不是编译器插件**，不修改 `moonc`，不依赖任何编译器内部 API；
- ❌ **不发明语法**，不注册新的 attribute —— 只用**已经合法的 doc comment**；
- ❌ **不做运行时反射**；
- ❌ **不声称扩展了 `derive()`** —— `derive()` 的行为完全不受影响；
- ⛔ **不是编译期执行引擎**：MoonBit 目前没有 comptime，生成发生在 `moon build` **之前**的独立阶段。这一点在 [`docs/项目方案（完善版）.md`](docs/项目方案（完善版）.md) 第 5.2 与第 9 节有详细论证。

## 3. 30 秒上手，上手易操作

```bash
# 1. 安装工具链）
```

### 请求语法

在你的 `.mbt` 文件里写普通的 MoonBit 代码，把派生需求放进 doc comment：

```moonbit
/// 用户信息。
///
/// @derive(validate, diff, field_names)
pub(all) struct User {
  /// 姓名
  /// @nonempty
  name : String

  /// 年龄
  /// @min(0) @max(150)
  age : Int

  /// 邮箱
  email : String
} derive(Eq, Debug)
```

- `@derive(a, b, c)` 写在**类型**的 doc comment 里；**书写顺序 = 输出顺序**（保证生成结果字节稳定）；
- `@nonempty` / `@min(n)` / `@max(n)` / `@positive` 写在**字段**的 doc comment 里，由具体规则解释；
- **没有 `@derive` 标记的类型，工具完全不碰**（零侵入）；
- 注释必须**紧邻**声明（中间隔一个空行就不会被采纳），这样上一段注释不会泄漏到下一个声明。

### 生成结果

`moon run cmd/main -- gen examples` 会在**源文件同目录**产出 `models_derive_gen.mbt`：

```moonbit
// ---------------------------------------------------------------------------
// Generated by MoonForge 0.1.0 -- DO NOT EDIT.
// source : models.mbt
// rules  : validate, diff, field_names
// regen  : moon run cmd/main -- gen <dir>
// ---------------------------------------------------------------------------

///|
pub fn User::validate(self : User) -> Result[Unit, String] {
  if self.name == "" {
    return Err("User.name must not be empty")
  }
  if self.age < 0 {
    return Err("User.age must be >= 0")
  }
  if self.age > 150 {
    return Err("User.age must be <= 150")
  }
  Ok(())
}
```

**为什么生成到同目录？** MoonBit 的包边界就是目录，私有字段只有同包可见。生成到同目录才能**直接访问字段，而不强迫你把字段改成 `pub`**。代价是会往你的源码目录里写文件——用文件头的 `DO NOT EDIT` 声明和 `.gitignore` 约定来管理。

> 生成文件是**应该提交进仓库**的：提交之后 `moon check` 就会真实地编译它，
> 生成代码的正确性由编译器裁决，而不是由工具的自我声明裁决。

## 4. 内置规则

| 规则 | 生成物 | 前置条件 |
|---|---|---|
| `field_names` | `T::field_names() -> Array[String]` | 无 |
| `validate` | `T::validate(self) -> Result[Unit, String]` | 注解只在 `String` 与内建数值类型白名单上生效 |
| `diff` | `T::diff(self, other) -> Array[String]` | 字段类型需实现 `Eq` |

三条规则**都只支持 struct**。给 enum 加上标记不会报错，而是得到一条"不适用"诊断。

`validate` 的注解语义：

| 注解 | 生效类型 | 生成 |
|---|---|---|
| `@nonempty` | `String` | `if self.f == "" { return Err(...) }` |
| `@positive` | `Int` / `Int16` / `Int64` / `UInt` / `UInt16` / `UInt64` / `Double` / `Float` | `if self.f <= 0 { ... }` |
| `@min(n)` | 同上 | `if self.f < n { ... }` |
| `@max(n)` | 同上 | `if self.f > n { ... }` |

注解落在白名单之外的类型上时，规则**跳过**它并在生成文件里留下说明行：

```moonbit
// moonforge: 跳过 Order.quantity 的校验注解（类型 Int 不在 String / 内建数值类型白名单内）
```

宁可少生成，也不生成编译不过或语义可疑的代码；而"**为什么不生成**"同样是要被解释的信息。

## 5. 命令参考

| 命令 | 作用 |
|---|---|
| `moonforge list-rules` | 列出已注册规则 |
| `moonforge explain <file.mbt>` | 打印解析结果（类型 / 字段 / 注解 / 命中规则），用于调试与可解释性 |
| `moonforge gen <path...>` | 生成 `*_derive_gen.mbt`（path 可为文件或目录，目录只扫描一层） |
| `moonforge check <path...>` | 校验生成物是否漂移；**有漂移则以非零码退出**（CI 用） |

退出码约定：`0` 成功 · `1` 检出漂移 · `2` 参数或路径有误。

任何错误都归一成**一行** `moonforge: ...` 提示，不会把运行期堆栈喷进 CI 日志：

```
$ moon run cmd/main -- explain validate
moonforge: 找不到路径：validate
    用法：moonforge explain <file.mbt>，例如 moonforge explain examples/models.mbt
```

`explain` 的实际输出：

```
$ moon run cmd/main -- explain examples/models.mbt

  struct User   (line 13)
    doc: 用户信息。
    @derive(validate, diff, field_names)
      [ok] validate 会生成代码
      [ok] diff 会生成代码
      [ok] field_names 会生成代码
    field name : String @nonempty
    field age : Int @min(0) @max(150)
    field email : String
```

## 6. 接进构建流程

生成器是 `moon build` **之前**的独立阶段（MoonBit 没有编译期钩子）。两种接法：

```bash
# 日常开发：改完源码跑一次
moon run cmd/main -- gen src

# CI：校验生成物没有漂移（改了源码却忘记重新生成 → 非零退出）
moon run cmd/main -- check src
```

`.github/workflows/ci.yml` 已经接好了这条链路。

## 7. 架构

```
 .mbt 源码
    │ (1) 词法分析        lexer.mbt        —— 只切 token，字符串/注释整体跳过
    ▼
 Token 流
    │ (2) 子集语法分析    parser.mbt       —— 只在花括号深度 0 认 struct / enum
    ▼
 类型模型 IR           type_model.mbt   —— TypeDef / FieldDef / Attr
    │ (3) 规则分派        rule.mbt         —— @derive(...) → Rule
    ▼
 代码片段              rules/*.mbt      —— field_names / validate / diff
    │ (4) 组装 + 文件头   codegen.mbt      —— 幂等、字节稳定
    ▼
 <同目录>/<主干名>_derive_gen.mbt
    │ (5) 和手写代码一起编译
    ▼
 moon check / moon test / CI
```

```
.
├── moon.mod / moon.pkg          # 模块与包元数据（本包 = 模块名 moonforge）
├── token.mbt  lexer.mbt         # 词法
├── type_model.mbt  parser.mbt   # IR 与子集语法分析
├── rule.mbt  codegen.mbt        # 规则接口 / 注册表 / 代码组装
├── rules/                       # moonforge/rules —— 内置规则
├── cmd/main/                    # moonforge/cmd/main —— CLI（executable）
├── examples/                    # 示例输入 + 已提交的生成物 + 端到端测试
├── *_wbtest.mbt                 # 白盒单元测试
├── scripts/e2e.sh               # 本地一条命令复现 CI
└── docs/                        # 一页项目说明 / 演示说明 / 项目方案（完善版）
```

### 可扩展性

`Rule` 是**公开的普通值**，规则集合是一个 `Array[Rule]`：

```moonbit
pub(all) struct Rule {
  name : String
  description : String
  gen : (TypeDef) -> String?     // None = 该规则不适用于这个类型
}
```

**新增一条规则 = 新增一个文件 + 在 `rules/registry.mbt` 的数组里加一项 + 补一组测试。**
不需要修改词法、语法、代码生成等任何核心代码。第三方也可以把本包作为库依赖，注入自己的规则集合——这是真实可用的扩展点，而不是"预留了接口"的口号。

## 8. 测试策略

| 层 | 覆盖对象 | 文件 |
|---|---|---|
| L1 | 词法：行首判定、注释剥离、字符串里的花括号不泄漏、非 ASCII 标识符、越界哨兵 | `lexer_wbtest.mbt` |
| L2 | 语法：类型原文精确切片（泛型 / 可选 / 包名 / 元组 / 函数类型）、注释紧邻性、深度守卫、enum 变体、不完整输入不崩溃 | `parser_wbtest.mbt` |
| L3 | 规则：每条规则的正例 + enum 不适用 + 白名单外的跳过与说明行 | `rules/rules_wbtest.mbt` |
| L4 | 金样：固定输入 → 断言输出**逐行等于**预期文本 | `rules/rules_wbtest.mbt` |
| L5 | 幂等：同一输入连续生成两次，输出**逐字节相同** | `codegen_wbtest.mbt` |
| L6 | 集成（真编译）：`examples/models_derive_gen.mbt` 随仓库提交，`moon check` 真实编译它 | `examples/` |
| L7 | 端到端 CLI：`gen` 后 `check` 返回 0；改动源文件后 `check` 返回非零 | `scripts/e2e.sh` + CI |
| L8 | CLI 地基：argv 前缀归一化、`is_command` 白名单、路径拆分与拼接（正 / 反斜杠） | `cmd/main/main_wbtest.mbt` |

`examples/models_wbtest.mbt` 里的测试**直接调用自动生成的方法**：

```moonbit
@debug.debug_inspect(u.validate(), content="Err(\"User.name must not be empty\")")
@debug.debug_inspect(a.diff(b), content="[\"age\"]")
```

这些方法在本仓库里**没有任何手写实现**——这就是"生成代码真的能用"的最直接证据。

```bash
$ moon test --target js
Total tests: 62, passed: 62, failed: 0
```

> **L6 是这套设计最关键的一条**：它把"工具输出的代码是正确的"从"我说它对"变成"编译器说它对"。

## 9. 已知限制（诚实清单）

| 限制 | 说明 | 影响 |
|---|---|---|
| 只解析**顶层类型定义** 不做别的操作| 函数体 / 表达式 / 宏只做括号计数并整体跳过 | 类型定义写在函数体内部（MoonBit 里不常见）不会被识别 |
| 字段类型**不做语义分析** | 取源码原文，由规则按字符串判断 | 别名类型（`type Age = Int`）不在数值白名单里，`@min` 会被跳过并留说明行 |
| 注解只写在一行 | `@min(0)` 的参数不支持换行书写 | 多行注解需写在同一行 |
| doc comment 必须**紧邻**声明 | 中间有空行则不被采纳 | 靠 `explain` 一眼可查 |
| `diff` 依赖字段类型的 `Eq` | 生成 `!=` | 前置条件已写进规则描述；节点在 `moon check` 阶段暴露 |
| 目录只扫描一层 | 避免误扫 `_build/` | 深层目录请显式传多个路径 |
| 生成文件头只写**文件名** | 不写绝对路径 | 保证跨机器字节稳定；同名文件在不同目录下的头部相同（不影响内容） |
